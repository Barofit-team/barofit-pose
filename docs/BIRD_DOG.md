# 버드독 실험용 판정 v0.5

Python과 JS에 동일하게 반영했다. 신규 다리 항목을 임상 검증된 기준으로 안내하지 않는다.

| 항목 | 계산 | 후보 경계 |
|---|---|---|
| LEG_HIGH | 어깨→골반 뒤쪽 연장선과 골반→무릎 방향 | 위쪽 20° 초과 |
| KNEE_BENT | 골반–무릎–발목 내각 | 155° 미만 |
| BODY_MOVEMENT | 지지 팔 쪽 몸통의 준비 기준 대비 수직 이동·기울기 | 12% / 12°; v0.4와 동일 |

유지 단계에서 0.25초 지속될 때 경고한다. 지지 무릎·전환 단계는 무릎 펴기 평가 대상이 아니다. 필요한 관절이 없으면 unknown이며 정상으로 집계하지 않는다.

- `thigh_alignment_deg`, `knee_angle_filtered_deg`를 사용한다. 기존 `leg_alignment_deg`는 골반→발목 진단값으로 유지한다.
- 새 항목 `left_knee_bent`, `right_knee_bent`, 코드 `LEFT_KNEE_BENT`, `RIGHT_KNEE_BENT`를 추가했다. 이전 `knee_extension` 키는 호환용 disabled다.
- 설정 `leg_alignment_deg`를 직접 넘기던 호출자는 `thigh_high_deg`로 변경해야 한다. `knee_min_deg`는 155다.
- 13개 기존 영상에서 160°는 정상 시범에 민감했다. 150/155/160/165/170°를 비교해 155°를 실험값으로 선택했다. 같은 자료를 선택과 평가에 사용했으므로 독립 성능 검증이 아니다.
- 새 허벅지 기준 20°는 평가 구간에서 경고가 없었다. 높이 검출이 검증됐다고 해석하지 않는다. 정상·오류의 분포가 겹쳐 추가 양성 사례가 필요하다.
- 등 윤곽은 별도 실험으로만 남긴다. 허리 곡률·회전 판정 및 반복 카운트는 아직 지원하지 않는다.

# 버드독 실험용 판정 v0.4 (이전)

당시 Python과 JS는 v0.4 판정 규칙을 사용한다.

- 몸통: 유지 단계에서 지지 팔 쪽 어깨·골반을 같은 손목 기준으로 비교한다. 준비 몸통 선에 수직인 이동이 몸통 길이의 12% 초과 또는 몸통 기울기 변화 12° 초과가 0.25초 지속되면 `BODY_MOVEMENT`다. 앞뒤 이동은 경고 조건에서 제외했다.
- `body.perpendicular_shift_ratio`, `body.along_shift_ratio`를 추가했다. `shift_ratio`는 기존 전체 이동량의 진단값으로 남긴다.
- 복귀 단계에서도 다시 뻗는 움직임이 확인되면 뻗기·유지로 돌아간다. 복귀 상태가 고정돼 이후 유지 구간을 놓치는 문제를 수정했다.
- 다리 정렬 20°와 지속 시간은 유지했다. 모두 공학적 실험값이며 문헌이 정한 정상/오류 경계가 아니다.
- 전환 단계의 몸통 평가는 `not_applicable`이다. 전 동작의 자세를 검증하는 기능은 아니며 해당 시간을 정상으로 집계하지 않는다.
- 정상 오경고는 일부 감소했지만 비스듬한 구도와 허리 과신전 누락은 남았다. 허리 곡률·축 회전, 반복 카운트는 지원하지 않는다.

# 버드독 실험용 판정 v0.3 (이전)

당시 `analysis.bird_dog`는 v0.3을 내보냈다. 준비·뻗기·유지·복귀 및 몸통 움직임은
v0.2와 동일하며, **다리 높이만 몸통 기준 정렬로 교체**했다.

- 어깨→골반 방향을 뒤로 연장한 벡터와 골반→발목 벡터의 부호 있는 2D 각도를 계산한다.
- 0°는 같은 방향, 양수는 몸통 연장선 위쪽. `leg_alignment_deg > 20`이 유지 단계에서
  0.25초 지속되면 기존 `LEFT_LEG_HIGH` / `RIGHT_LEG_HIGH` 코드를 출력한다.
- 20°는 문헌 기준이 아니다. 기존 4명 영상에서 10/15/20/25°를 비교해 선택한 실험값이다.
- 화면 y축 높이 비율은 진단용으로만 남긴다. 새 출력은 `leg_alignment_deg`,
  `leg_alignment_distance_ratio`, `thigh_alignment_deg`다.
- 낮게 뻗는 정상 지도 방식이 있으므로 음수 각도를 자동 오류로 분류하지 않는다.
- 바닥 방향을 추정하지 않으므로 실제 바닥과 수평이라고 판정하지 않는다. 측면/준측면,
  뒤집히지 않은 카메라 조건이다. 몸통 자체가 잘못 기울어진 경우를 이 각도만으로 잡지 못한다.
- 몸통 움직임 경고는 기존 오경고 문제가 남아 있으며, 허리 곡률이나 회전으로 해석하면 안 된다.
- 과거 결과와 비교 시 `engineVersion`으로 구분할 것. 푸시업·플랭크는 변경하지 않았다.

# 버드독 실험용 판정 v0.2 (이전)

## 현재 활성화된 동작

당시 `analysis.bird_dog`는 v0.2를 내보냈다. v0.1 구현은 `legacy_v01.py`에 비교용으로 보존했다.
공통 프레임 입력은 동일하며 기존 푸시업·플랭크 모듈은 변경하지 않았다.

- 준비 → 뻗기 → 유지 → 복귀를 다리별로 구분.
- 다리 높이: 유지 단계에서 `(골반 y − 발목 y) / 몸통 길이 > 0.08`이면 후보.
- 몸통 움직임: 지지 손목/무릎 기준 어깨·골반 이동량이 준비 몸통 길이의 0.12 초과,
  또는 준비 몸통 선 기울기 대비 12° 초과이면 후보. 동작 전체에서 평가.
- 후보가 0.25초 지속되면 경고. 숫자는 모두 검증할 엔지니어링 값.
- 무릎·팔꿈치·손 정렬 등 나머지 기존 경고는 `disabled`.
- `reference` 인자는 제거. 안정된 준비 구간 0.4초에서 자동 기준점 확보.
  먼 쪽 무릎이 가려져도 보이는 쪽으로 확보 가능. 준비 자세가 의학적으로 정상이라는 뜻은 아니다.
- `body`에 기준 확보 여부, 관측 쪽, 지지 관절 번호, 이동 비율과 기울기 변화를 반환.
- `unknown`은 관측 불가, `not_applicable`은 해당 단계가 아님. 정상/준수로 집계하지 않음.
- 관측 공백·크기 변경·준비 형태 이탈 시 기준 초기화. 다시 확보할 때까지 몸통 평가는 보류.

정상 비교 영상은 원본 9초부터 준비 장면을 입력한 뒤 10초부터 집계했다:

```sh
python -m examples.bird_dog_video source.mp4 --model pose.task --output results/normal --start 10 --end 17.6 --warmup-start 9 --ffmpeg /path/to/ffmpeg
```

[실행 결과와 한계](BIRD_DOG_V02_REVIEW.md). 허리 곡률·회전 판정과 반복 카운트는 여전히 지원하지 않는다.

# v0.1 설계 기록 (아래 설정은 현재 활성 규칙이 아님)

2026-10-20. Python 분석만 구현. 임상 검증, 제품 완료, 앱 이식 완료를 의미하지 않는다.
지금은 관절 좌표 → 항목별 상태·코드·측정값 출력. 반복 카운트는 아직 없으며 `count:null`.

## 근거와 구현의 구분

- [ACE](https://www.acefitness.org/resources/everyone/exercise-library/14/bird-dog/):
  손–어깨, 지지 무릎–골반 정렬, 반대쪽 팔다리 뻗기, 몸통 안정성.
- [NHS](https://dynamichealth.nhs.uk/help-and-advice/mid-back-pain/):
  척추를 제어할 수 있는 높이까지만 들고 좌우 이동을 제한한다.
- [McGill & Karpowicz 2009](https://pubmed.ncbi.nlm.nih.gov/19154838/):
  초록 확인. 운동별 근활성과 3D 척추 자세 연구이며 아래 숫자의 출처가 아니다.
- [다열근 연구 2021](https://pmc.ncbi.nlm.nih.gov/articles/PMC8136566/):
  실험 자세·유지 시간을 앱 오류 경계값으로 옮기지 않는다.

현재 모든 숫자는 엔지니어링 후보값이다. 정상/오류 경계를 문헌이 검증했다고 표현하지 않는다.

## 입력·출력

공통 33×5 MediaPipe 프레임을 `BirdDogAnalyzer.push_frame(frame)`에 전달한다.
화면 픽셀로 변환하여 가로세로 비율을 보정한 후 각도·거리를 계산한다.
측면에 가까운 고정 카메라, 전신, 1명을 전제로 한다. 자동 촬영각 판별은 없다.
카메라 기울기는 `camera_roll_deg`로 직접 지정 가능하며 기본 0°가 자동 보정을 뜻하지 않는다.
원근 오차는 보정하지 않는다. 양쪽 관절이 안 보이면 각 항목만 unknown.

`side:null`은 양쪽을 독립 평가한다는 뜻이다. 한쪽만 보이면 그쪽 항목만 평가한다.
`items`, `codes`, `metrics`, `phase`, `tracking`을 반환한다.
관측 범위 밖의 unknown은 정상이나 준수에 포함하지 않는다.

## 계산과 임시 설정

| 항목 | 계산 | 현재 실험값 |
|---|---|---|
| 지지 손 정렬 | 어깨–손목 수평 차이 / 몸통 길이 | 0.25 초과 |
| 지지 무릎 정렬 | 골반–무릎 수평 차이 / 몸통 길이 | 0.25 초과 |
| 뻗은 팔꿈치·무릎 | 세 관절 내각 | 155° 미만 |
| 팔다리 과도한 들기 | 어깨→손목, 골반→발목의 수평 대비 위쪽 각도 | 20° 초과 |
| 반대쪽 조합 | 뻗은 팔·다리의 좌우 비교 | 같은 쪽이면 후보 오류 |
| 몸통 기울기 변화 | 검토된 준비 자세의 어깨–골반 선과 차이 | 12° 초과, 기준 없으면 unknown |

몸통 길이는 명시적으로 주어진 reference.length, 없으면 현재 프레임의 어깨–골반 길이.
카메라 이동·몸통 회전으로 분모가 바뀔 수 있다. 준비 자세를 정상이라고 자동 가정하지 않는다.
`reference={side:{length,trunk_deg}}`는 같은 좌표 크기·구도의 검토된 기준만 전달한다.
현재 영상 실험은 reference를 전달하지 않았으므로 몸통 변화 경고를 평가하지 않았다.

뻗기 후보: 손목이 어깨 앞, 무릎이 골반 뒤로 몸통 길이 0.30 이상 이동.
앞으로 잘못 짚은 손을 뻗은 팔로 오인하지 않도록 팔 전체 선이 수평 아래 60°보다 높을 때만 팔 뻗기로 분류한다.
준비 여부: 손목/무릎이 어깨/골반 아래에 있고 몸통 기울기 40° 미만.
준비 판별은 서비스 준비/시작 감지의 검증 완료를 의미하지 않는다.
뻗기 감지 뒤 0.35초부터 펴기·높이를 평가하며 실제 끝점/정지 감지가 아니다.
오류 조건 0.4초 지속 시 경고, 0.4초 이상 프레임 공백 또는 관측 누락이면 누적을 끊는다.
confidence 0.5, 카메라 구도 제한, 지속시간 역시 검증할 구현 설정이다.

## 의도적으로 하지 않는 판정

- 낮게 뻗으면 무조건 오류: 허리 안정성을 위해 높이를 제한한 정상 변형이 있다.
- 허리 곡률/척추 중립: 요추 랜드마크가 없으므로 not_supported.
- 축 방향 회전: 단일 측면 2D 어깨/골반 기울기로 실제 회전을 단정하지 않음.
- 근육 활성·호흡·통증: 관절만으로 추정하지 않음.
