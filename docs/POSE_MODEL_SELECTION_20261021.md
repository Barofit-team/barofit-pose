# 관절 추출 모델 비교와 선정 기록

기준일: 2026-10-21

**MediaPipe Pose Landmarker Full을 기본 모델로 유지한다.** MoveNet Lightning은 CPU 처리 시간이 짧지만, 이번 서비스 영상에서는 카운트 복구와 별개로 팔꿈치 관측 부족과 초기 추적 흔들림이 남았다. 자세 피드백에 필요한 관절의 안정성을 우선했다. MoveNet은 경량화 후보로 보존한다.

## 비교 목적과 방법

관절 추출 모델을 교체했을 때 속도뿐 아니라 실제 횟수·자세 피드백이 유지되는지 확인했다. 푸시업·플랭크·버드독·점핑잭 각 4개, 총 16개 영상 구간을 같은 프레임과 시각으로 처리했다. 관절을 공통 입력 형태로 변환하고 기존 운동별 판정 로직에 연결했다.

- 최대 20fps, 공통 영상 너비 640px. 원본 프레임률이 낮으면 원본에 맞췄다.
- MoveNet은 동적 인물 크롭과 원점수 0.3 기준을 적용했다. MediaPipe의 visibility와 같은 확률로 취급하지 않았다.
- 푸시업은 MoveNet 연결부의 결측 처리를 보완하고, 두 모델에 동일한 수행 상태 구분을 적용한 결과를 최종 비교했다.
- 영상 육안 검토와 결과 로그를 대조했다. 전체 관절·모든 회차에 독립 정답을 부여한 정확도 벤치마크는 아니다.

## CPU 처리 속도

Ryzen 7 7800X3D에서 전처리·추론·관절 변환 시간을 측정했다. 디코딩·공통 축소·렌더링·초기화는 제외하고 각 사례의 초기 10프레임은 워밍업으로 제외했다. MediaPipe는 기본 스레드, MoveNet LiteRT는 4스레드다.

| 구성 | 중앙값 | 95백분위 |
|---|---:|---:|
| MediaPipe Full | 12.68ms | 13.58ms |
| MoveNet Lightning 전체 화면 | 2.68ms | 4.06ms |
| MoveNet Lightning 동적 크롭 | 2.84ms | 4.27ms |

동적 크롭 MoveNet의 중앙 처리 시간은 MediaPipe의 약 22%였다. 이 수치는 PC에서 모델 처리 구간을 측정한 값이며, Android의 전체 지연·발열·배터리 성능을 뜻하지 않는다.

## 트래킹과 피드백

| 관찰 대상 | MediaPipe | MoveNet Lightning |
|---|---|---|
| P5 오류 영상 초반, 손목이 일부 잘리는 구간 | 사용자 육안 검토에서 상대적으로 안정적인 추적 | 사용자 육안 검토에서 관절 흔들림이 더 두드러짐 |
| 같은 영상의 이후 구간 | 안정적으로 보임 | 안정적으로 보임 |
| P5 정상 영상의 팔꿈치 | 팔꿈치 신호로 반복 검출 | 보완 후 6회 검출했지만 팔꿈치 평가는 5회 보류 |
| 모델 교체 시 고려점 | 기존 33관절 기반 규칙과 연결 검증 축적 | 17관절 매핑·점수 기준·결측 처리의 별도 검증 필요 |

MoveNet의 P5 정상 영상 무카운트 원인은 팔꿈치 누락 때 전체 후보 동작을 초기화하던 연결부에도 있었다. 어깨 왕복을 유지하도록 수정한 뒤 0회에서 6회로 복구됐다. **카운트 복구가 팔꿈치 추적 개선이나 피드백 가능 범위 확대를 의미하지는 않는다.**

## 푸시업 카운트 비교

공통 수행 상태 구분까지 적용한 최종 결과다. 표의 숫자는 모델 출력이며 정답 횟수로 간주하지 않는다.

| 영상 | MediaPipe | MoveNet Lightning |
|---|---:|---:|
| P2 정상 | 12 | 12 |
| P2 오류 | 12 | 13 |
| P5 정상 | 7 | 6 |
| P5 오류 | 6 | 7 |

- P5 정상: 수행 상태 구분으로 MediaPipe의 종료 동작 오카운트 2회가 제거됐다(9→7). 마지막에 충분히 복귀하지 못하고 무너지는 동작은 여전히 MediaPipe가 세고 MoveNet은 세지 않았다.
- P5 오류: MoveNet의 일어서는 동작 오카운트 1회가 제거됐다(8→7).
- P5 오류에서 사용자가 확인한 시도는 9회였다. 그 기준으로 MediaPipe는 3회, MoveNet은 2회 놓쳤다. 작은 움직임까지 세도록 탐지 조건을 확대하지 않는 정책을 유지했다.
- 따라서 카운트만으로 MediaPipe의 일관된 우위를 주장할 수 없다. 추출 좌표와 후처리 규칙을 함께 검토해야 한다.

## 다른 운동에서 확인한 차이

| 사례 | MediaPipe | MoveNet 동적 크롭 0.3 |
|---|---|---|
| NASM 점핑잭 | 4회 | 4회 |
| Kickstand 점핑잭 | 19회 | 2회 |
| NHS 버드독 | 1회 / 유지 7.91초 | 1회 / 유지 8.07초 |
| P2 정상 플랭크 | 유효 유지 14.90초 | 유효 유지 14.90초 |
| 무릎 굽힘 오류 플랭크 | 유효 유지 8.50초 | 유효 유지 2.77초 |

플랭크 시간 차이는 좌표·관측 가능성·판정의 차이가 누적된 출력이다. 더 짧거나 긴 시간을 자동으로 더 정확하다고 평가하지 않았다. 다른 운동의 MoveNet 연결은 비교용이며, 전 운동의 운영 지원을 확정한 것은 아니다.

피드백에서는 플랭크의 골반 올라감·무릎 굽힘 경고 종류는 두 모델에 공통으로 나타났지만 경고 구간 길이가 달랐다. 버드독 다리 과상승 사례는 유지 단계와 관측 가능한 관절이 달라 일부 경고가 빠졌다. NASM 점핑잭은 두 모델 모두 4회·무경고로 일치했다. 항목별 경고 수는 평가 가능한 회차와 시간이 다르므로 그대로 정확도로 환산하지 않았다.

## 선정 이유와 남은 확인

1. 현재 목적은 빠른 관절 추출에 더해 안정적인 자세 피드백을 제공하는 것이다. MoveNet은 카운트가 복구돼도 평가에 필요한 관절이 부족한 사례가 있었다.
2. MediaPipe는 이번 불안정한 촬영 구간에서 상대적으로 안정적인 추적을 보였고, 기존 운동별 연결 검증이 축적돼 있다.
3. MoveNet의 속도 이점은 유지한다. 저사양 기기에서 병목이 확인되면 실제 Android 지연·발열과 항목별 판정 보류율을 함께 비교한다.
4. MediaPipe의 미완성 복귀 카운트와 작은 움직임 누락은 남은 한계로 기록한다. 모델 선정과 개별 판정 결함을 구분한다.

## 포트폴리오 설명

> 동일 운동 영상에 여러 관절 추출 모델을 연결해 CPU 처리 시간, 관절 추적 안정성, 카운트와 자세 피드백을 비교했다. MoveNet Lightning은 동적 크롭 기준 중앙 처리 시간이 2.84ms로 MediaPipe Full의 12.68ms보다 짧았지만, 일부 푸시업에서 팔꿈치 관측 부족으로 자세 평가가 보류됐다. 서비스의 핵심인 자세 피드백 안정성을 우선해 MediaPipe를 기본으로 유지하고, MoveNet은 경량화 후보로 남겼다. 비교 과정에서 드러난 결측 처리와 운동 종료 오카운트는 연결부 및 공통 수행 상태 로직으로 보완했다.
