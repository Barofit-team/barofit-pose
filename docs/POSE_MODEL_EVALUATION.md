# 관절 추출 모델 선정 절차

작성일: 2026-10-20. 평가 설계이며, 후보 모델의 실측 성능표가 아니다.

## 목적과 기준선

모바일에서 푸시업·플랭크 관절을 안정적으로 추출하고 기존 카운트와 자세 피드백을 유지하거나 개선하는 모델을 선택한다.
기준선은 현재 MediaPipe Pose Landmarker Full과 고정된 barofit-pose 판정 로직이다.
스쿼트는 담당자의 로직과 검토 데이터가 준비된 뒤 같은 절차로 추가한다.

공개 벤치마크는 후보 선정 자료다. 다른 하드웨어·입력 크기로 측정한 FPS를 직접 순위로 비교하지 않는다.
모델뿐 아니라 사람 검출, 크롭, 좌표 복원, 추적, 평활화가 포함된 실행 구성을 기록한다.

## 후보 및 단계

1. MediaPipe Full을 기준선으로 재현한다.
2. MediaPipe Lite/Heavy, MoveNet Lightning/Thunder, RTMPose-s를 소규모 개발 세트에서 실행한다.
3. YOLO Pose 소형 모델은 배포 조건과 구현 비용을 검토한 추가 후보로 둔다.
4. 개발 세트에서 성능·통합 가능성을 확인한 상위 2개와 Full을 실제 Android 앱에서 비교한다.
5. 설정을 확정한 뒤 사람 단위로 분리한 최종 테스트 세트를 한 번 평가한다.

## 데이터와 정답

- 기존 Mendeley 푸시업과 측면 플랭크 영상은 이미 기준 조정에 사용했으므로 개발·회귀 검증 세트로 취급한다.
- 최종 테스트에는 기준 조정에 사용하지 않은 사람을 확보한다. 부족하면 일반화 검증 미완료로 표시한다.
- 같은 사람의 정상/오류, 다른 시점, 같은 원본에서 잘린 영상은 같은 분할에 둔다.
- 인물을 식별할 수 없으면 unknown으로 기록하고 사람 독립 테스트라고 주장하지 않는다.
- 사람·출처·원본 영상·촬영 방향·정상/오류 종류·가림·프레임 잘림·파일 SHA-256을 목록에 기록한다.
- 결과를 보기 전에 비교 영상을 고정한다. 쉬운 정상, 오류, 가림, 준비/종료, 작은 움직임 사례를 포함한다.
- 폴더의 good/bad는 참고 라벨이다. 개별 관절 오류의 정답으로 그대로 사용하지 않는다.
- 사람이 반복 시작/끝, 실제 시도 횟수, 오류 항목별 구간, 판정 불가 구간을 검토한다.
- 표본 프레임에 보이는 관절을 수동 표시한다. 가려진 관절 위치는 억지로 정답을 만들지 않는다.
- 일부 라벨은 다른 검토자가 재검토하고 불일치를 기록한다. 전문가 검토가 없으면 전문 자세 정답으로 표현하지 않는다.

## 공정한 연결

공통 좌표는 좌우 어깨·팔꿈치·손목·골반·무릎·발목의 이미지 평면 좌표로 맞춘다.
크롭·리사이즈·좌우 반전은 원본 영상 좌표로 복원한다.
다른 모델에 없는 3D 좌표나 visibility/presence를 관측값인 것처럼 생성하지 않는다.
모델의 confidence는 MediaPipe visibility/presence와 동등한 수치가 아니다.
모델별 품질 게이트의 의미와 개발 세트에서 선택한 임계값을 기록한다.

두 결과를 구분해 저장한다.

1. 기존 기하학·카운트 기준 고정: 모델 교체 시 영향 평가. 좌표 변환과 품질 게이트만 모델에 맞게 처리한다.
2. 모델별 개발 세트 보정: 동일한 탐색 예산으로 보정 후 미사용 사람에게 적용한다.

원시 좌표와 실제 판정에 입력된 평활화 좌표를 함께 보존한다.
모델별 기본 추적의 차이를 숨기지 않는다. 정지 이미지 실험과 연속 영상 실험도 구분한다.

## 평가 지표

| 영역 | 지표 및 집계 |
|---|---|
| 관절 정확도 | 수동 정답 대비 픽셀 오차와 정답 인체 크기로 정규화한 오차. 관절별 분포와 누락률 함께 표시 |
| 추적 안정성 | 필수 관절 확보율, 연속 누락 시간, 좌우 뒤바뀜. 정지 구간 좌표 흔들림은 정확도와 별도 표시 |
| 카운트 | 영상별 실제/예측 횟수, 절대 오차, 과대/과소 카운트. 동일 총횟수라도 시점이 다르면 이벤트 매칭에서 구분 |
| 자세 피드백 | 항목별 precision/recall, 정상 구간 오경고, 오류 구간 누락, 판정 보류율 및 판정 가능 범위 |
| 반응성 | 오류 발생에서 판정 출력까지 지연. TTS 재생 지연은 별도 |
| 실행 성능 | 초기화/첫 추론/워밍업 후 p50·p95 처리 시간, 처리 FPS, 프레임 드롭·결과 지연 |
| 모바일 부담 | 모델 용량, 앱 메모리, 연속 실행 후 성능 저하와 기기 온도 조건 |

오류 이벤트의 병합 간격과 매칭 허용 시간은 측정 전 설정 파일에 고정한다.
판정 보류를 정상으로 바꾸지 않고, 가시 구간만의 성능과 전체 구간에서의 누락을 함께 보고한다.
영상 길이에 따른 편향을 막기 위해 사람별·영상별 결과와 전체 결과를 함께 제공한다.
불확실성은 가능하면 사람 단위 재표집으로 추정한다. 프레임들을 독립 표본으로 간주하지 않는다.

## 실행 조건

- 동일 원본 영상과 타임스탬프를 사용하며 기존 목표 15fps를 초기 비교 조건으로 둔다.
- 같은 기기에서 같은 CPU/GPU 조건끼리 비교한다. 모델별 권장 입력 크기는 기록하며 무조건 동일 크기를 강제하지 않는다.
- 모델 순수 추론 시간과 검출·전처리·추적·판정을 포함한 전체 처리 시간을 따로 측정한다.
- 반복 측정하며 모델 실행 순서를 바꾼다. 휴대폰 장시간 테스트에서는 시작 온도와 충전 상태를 기록한다.
- PC 결과를 모바일 성능으로 대체하지 않는다. 1차 실기기는 Galaxy S25이며 지원 범위를 넓히면 다른 기기도 추가한다.
- 모델 버전·해시, 코드 커밋, 런타임, 양자화, 스레드 수, 입력 크기, 가속기, 설정, 원시 결과를 저장한다.

## 선정 기준

정확도 하나를 합산한 임의 점수로 선정하지 않는다.
개발 세트에서 모바일 지연 허용치와 오경고/카운트 허용 오차를 정하고, 최종 테스트 전에 고정한다.
모바일 동작·배포 조건을 통과한 후보 중 현재 Full보다 품질이 나빠지지 않으면서 빠르거나,
추가 비용에 비해 명확한 품질 개선이 있는 후보를 고른다.
차이가 작거나 불확실하면 검증된 Full을 유지한다.

산출물: 데이터 분할 목록, 정답 검토 기록, 실행 설정, 모델별 원시 결과, 같은 영상의 뼈대 비교,
실패 사례, 모바일 측정표, 선택·탈락 이유. 이번 문서는 절차 확정이며 실제 실험 완료를 뜻하지 않는다.
