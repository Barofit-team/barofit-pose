2026.10.20 기준. 앱에 들어갈 기능을 검증하는 단계이며, 임상적 정확도나 모든 사용자에 대한 성능을 보장하는 표가 아니다.

|---|---|---|
| 푸시업 | 움직임 시도 카운트, 골반 처짐·올라감, 팔꿈치 굽힘, 상체 이동·손 위치 피드백 | Android·웹에서 1차 동작 검증. 준비 움직임·추적 끊김·일부 정상 경고 보완 필요. 팔꿈치 벌어짐을 직접 분류하지 않으며 상체·손은 대리 지표 |
| 플랭크 | 골반 정렬, 어깨–팔꿈치 정렬, 무릎 펴기 | 소량의 영상·이미지에서 개발 검증. 실제 유지 시간·자동 시작·종료 감지는 미구현 |

| 버드독 | 준비·뻗기·유지·복귀 단계, 몸통 기준 다리 정렬·몸통 움직임 | 실험 중. 정상 오경고·오류 누락이 남음. 횟수·유지 시간·허리 곡률·축 회전 미지원 |

모든 실시간 판정은 MediaPipe 관절 좌표를 받는 운동별 규칙으로 처리한다. 웹은 영상을 서버에 보내지 않는다. 영상 화면의 각도·거리와 실제 신체 각도는 다를 수 있다.

## 스쿼트 원본과 웹의 차이

원본: [`feat/squat-colab`, `54c56ab`](https://github.com/Barofit-team/barofit-pose/blob/54c56ab77c27d9e4b40314bc945519cca645607a/examples/notebooks/barofit_squat_comparison.ipynb).

- 순수 엔진은 원본 수식과 임계값을 유지했다. 서기 ≥155° → 굽힘 ≤125° → 서기로 카운트하고, 회차의 최소 무릎 각도 >100°이면 깊이 부족으로 기록한다. 경고 때문에 완료 횟수를 취소하지 않는다.
- 125°에 도달하지 않는 얕은 움직임은 세지 않는다. 푸시업의 시도 카운트 정책과 다르다.
- 원본은 영상 전체에서 유효한 무릎 좌표가 많은 쪽을 선택한다. 웹은 서있는 준비 상태에서 어깨·골반·무릎·발목이 0.4초 확보된 쪽을 선택한다.
- 웹은 관절 누락·좌우 전환·일시정지에서 미완성 회차를 끊는다. 완료 횟수는 유지한다. 이 때문에 원본 노트북과 웹 횟수가 달라질 수 있다.
- 동일 좌표 946프레임에서 Python·JS 순수 엔진의 상태·경고·횟수가 일치했다. 정상 후보 9회·오류 후보 0회였고, 웹 자동 선택은 7회·0회였다. 이 영상에는 배경 인물과의 추적 혼선이 있어 정확도 수치로 사용하지 않는다.

## 결과 해석

- `count`와 자세 결과는 별개다. 평가할 수 없는 구간은 정상으로 계산하지 않는다.
- 스쿼트 깊이는 완료 **회차 기준**, 몸통 기울기는 평가 가능한 **시간 기준**이다.
- 플랭크·버드독의 `observedSeconds`는 관측된 영상 시간이다. 실제 운동 유지 시간이 아니며 `holdSeconds`는 `null`이다.
- 실험용 스쿼트·버드독은 루틴에 확정 제공하는 운동과 구분한다.

## 연동·테스트

```js
import {PushupAnalyzer, PlankAnalyzer, SquatAnalyzer, BirdDogAnalyzer} from '@barofit/pose';
const analyzer = new SquatAnalyzer(); // 실험용, 자동 좌우 선택
const result = analyzer.pushFrame({timestampMs, width, height, landmarks});
```

입력은 33개의 `[x, y, z, visibility, presence]`와 영상 크기·밀리초 시각이다. 공통 결과에 운동별 상태·수치·이벤트를 담는다. 자세한 형식은 [입출력 규격](IO_CONTRACT.md), 실험 웹 설치는 [실험 페이지 안내](../examples/web/experiments/README.md)를 참고한다.

`npm test`로 JS 전체 테스트를 실행한다. 버드독은 Python 참조 구현에서 추출한 합성 798프레임의 고정 입력·기대 결과를 비교하므로 별도 Python이나 미공개 분석 코드가 필요 없다. 이 검사는 구현 일치 확인이며 운동 자세 정확도 검증이 아니다.
